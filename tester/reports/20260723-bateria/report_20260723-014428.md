## Mejoras propuestas (priorizadas — para el equipo de código)

1. **[reserva_web] Brain / RAG (Conocimiento del dominio)** — Incorporar knowledge chunk explícito sobre procesos de ITV (reserva previa obligatoria web) e instrucciones de preferencia de usuario (ej. 'si usuario pide reserva, prioriza slowbrain').
   · _por qué_: El asistente inventó restricciones ('hay que ir en persona') y falló al entender la solicitud de ejecución web como un simple apunte de agenda.
2. **[reserva_web] Router / Trigger de Escala** — Refinar el 'intent classifier' para que las frases 'reserva por web', 'hazlo tú', 'coge cita' disparen obligatoriamente `escalate_to_slowbrain` + `tool_use_browser`.
   · _por qué_: El objetivo del escenario (acción web) se falló por completo al no escalarse y no activarse el worker de navegación.
3. **[reserva_web] Estrategia de respuesta (Buscador vs Web)** — Prohibir respuestas textuales de 'cómo hacer cosas' si la intención es acción. Forzar un handshake: 'Voy a entrar en la web...' y lanzar el navegador.
   · _por qué_: Zaelar ofreció explicaciones y alternativas (agenda) en lugar de ejecutar la tarea demandada, reduciendo la utilidad a cero.
4. **[reserva_web] Memory / Entity Resolution** — Aumentar el peso de las últimas intervenciones del usuario en el prompt de contexto para fijar el nombre correcto (Ricart) frente a alucinaciones de memoria antigua (Gicard/Hikar).
   · _por qué_: Llamar al usuario por nombres incorrectos degrada la naturalidad y la confianza en el sistema.
