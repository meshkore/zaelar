## Mejoras propuestas (priorizadas — para el equipo de código)

1. **[widget] Brain/Prompting (Intent Fulfillment)** — Instruir al LLM para que procese TODAS las partes de una solicitud compuesta (AND lógico). Si el usuario pide A Y B, debe ejecutar ambos; si falla uno, notificarlo.
   · _por qué_: Zaelar ignoró la solicitud del reloj (reloj) en el primer turno, reduciendo la utilidad percibida.
2. **[widget] Sistema de Acción de Widgets (Tool Use)** — Implementar confirmación estricta de renderizado: el LLM no debe decir 'Te muestro...' hasta recibir un evento de éxito del Frontend/Canvas. Diferenciar entre renderizar widget (Canvas) y enviar datos de texto (Chat).
   · _por qué_: Zaelar afirmó mostrar la agenda y el clima, pero la traza solo repite tags de datos/logs ('widget:data') sin una acción clara de 'canvas' o 'show' para el usuario.
3. **[widget] Gestión de Timeouts y Endpointing** — Añadir un fallback 'latente' (non-verbal) o un 'beat' de procesamiento si la generación de texto tarda >2s, para evitar silencios absolutos que parecen desconexiones.
   · _por qué_: El silencio en el turno 2 rompe la fluidez y da sensación de sistema congelado.
4. **[widget] Control de Reinicio de Contexto (STT/Brain)** — Revisar el VAD/Endpointing o el 'System Prompt' que induce el reinicio del contexto. El cerebro interpretó la solicitud del tiempo como una pregunta 'aislada' (prompt: '...tiempo que hace hoy,') perdiendo el contexto del reloj.
   · _por qué_: La traza sugiere que el cerebro cortó la frase del usuario para procesar solo el final, ignorando el inicio.
