2. **[navegador_moto] Orquestación de turnos / State Machine** — Añadir un flag 'task_in_progress' en el contexto. Si el usuario confirma ('Estoy atento'), el LLM debe emitir un ack corto (ej. 'Genial, te aviso') y pasar a modo de escucha pasiva.
   · _por qué_: Zaelar entra en bucle de confirmación porque cree que debe responder a cada input del usuario reiterando la tarea en lugar de dejar que el proceso asíncrono corra.
3. **[navegador_moto] Memory / Entity Resolution** — Normalizar el nombre del usuario al inicio de sesión y forzar un único alias en el prompt del sistema.
   · _por qué_: El usuario se llama Ricart/Ricard y Zaelar le llama Ricardo, lo cual desencaja la naturalidad y denota pega de datos.
4. **[navegador_moto] Manejo de Errores (Flash Brain)** — El 'susurro' del sistema que inyecta instrucciones de reparación no debería ser visible en la traza como un prompt inyectado si genera ruido; el modelo de repente responde a 'Ricardo' debido a esta inyección.
   · _por qué_: El sistema intenta reparar la respuesta cambiando el nombre al azar, lo que confunde la coherencia de la conversación.
