## Mejoras propuestas (priorizadas — para el equipo de código)

1. **[reserva_web] Brain / Memory / Routing** — Implementar un 'hard break' en el ruteo: si el usuario introduce una nueva petición explícita ('Reserva ITV') con alta intención, debe sobrescribir cualquier contexto o 'memory state' previo de UI.
   · _por qué_: Zaelar se 'atasca' en el contexto anterior (resultados coches) y es incapaz de pivotar a la nueva tarea sin que el usuario insista.
2. **[reserva_web] Frontend / Browser Orchestration** — Asegurar que la señal 'escalate_to_slowbrain' conlleve una transmisión inmediata de estado al widget del navegador (ej. 'loading' o primera URL), en lugar de solo mostrar el contenedor vacío.
   · _por qué_: La traza muestra eventos de navegador pero el comportamiento (bucle mudo, 'te dejo trabajar') sugiere que el worker no está recibiendo el DOM o las instrucciones para navegar.
3. **[reserva_web] Voice Persona / Prompting** — Prohibir frases de cierre unilateral como 'Te dejo trabajar' o 'Vale, te dejo' durante una tarea de ejecución. El prompt debe forzar un estado de 'feedback continuo' (ej: 'Estoy entrando en la web...', 'Buscando fecha...').
   · _por qué_: Rompe la ilusión de agencia y hace parecer que el bot ha colgado o fallado, cuando simplemente está procesando.
