## Mejoras propuestas (priorizadas — para el equipo de código)

1. **[email_reply] Cerebro / Gestión de Contexto (Memory)** — Implementar un 'hard rule' en el prompt del sistema: 'NUNCA repitas literalmente la respuesta anterior si el usuario solicita aclaraciones; reformula o acota la respuesta'.
   · _por qué_: El usuario recibió un 'loop' de texto idéntico en los turnos 2 y 3, lo que rompe la inmersión y denota falta de atención al historial inmediato.
2. **[email_reply] Tool Calling / Fallback Logic** — Corregir la lógica de fallback para 'navegador' o 'login'. El sistema ha interpretado 'vincular cuenta' o 'conectar correo' como una orden de abrir una URL específica (wallapop.com) en lugar de mostrar el widget de Mensajería.
   · _por qué_: Existe una divergencia crítica entre la intención verbal (conectar email) y la acción técnica (abrir navegador en web ajena), indicando que el tool-chooser está mal entrenado o el fallback busca keywords erróneas.
3. **[email_reply] Brain - Generación de 'Lead-ins' (Relleno)** — Generar el 'lead-in' dinámicamente en función de la respuesta final o eliminarlo si la respuesta tarda menos de X segundos. Evitar usar 'Mmm...' o 'A ver...' genéricos si el contenido final es afirmativo.
   · _por qué_: Se observan rellenos tipo 'A ver, a ver...' seguidos de una respuesta estándar ('Perfecto, adelante'), lo que sonan mecánicos y robóticos.
4. **[email_reply] Validación de Estado (State Awareness)** — Inyectar el estado de la UI (mensajería vs navegador) en el prompt de few-shotings para evitar que el bot diga 'Te muestro Mensajería' mientras abre 'Navegador'.
   · _por qué_: El usuario escucha 'Te muestro Mensajería' pero ve Wallapop, lo que genera desconfianza y confusión sobre qué pasos debe seguir.
