## Mejoras propuestas (priorizadas — para el equipo de código)

1. **[susurro_reparacion] Brain Memory / LLM Prompting (Context Window)** — Inyectar explícitamente la última interacción fallida detectada por el auditor en el contexto del prompt principal del FlashBrain (ej. 'Nota: El usuario acaba de corregirte pidiendo la agenda, lo anterior fue un error').
   · _por qué_: Zaelar procedió ciegamente a cumplir la orden anterior (reloj) ignorando que el usuario había corregido la intención (agenda) en el turno inmediato anterior, lo que indica pérdida de contexto inmediato.
2. **[susurro_reparacion] Susurro Auditor (Output / Template)** — Implementar un post-proceso en el output del LLM auditor para verificar comillas cerradas o integridad de la frase antes de inyectar el 'repair_say' en la cola. Forzar un stop sequence si el texto se corta.
   · _por qué_: El texto del susurro aparece truncado ('...revisión de obli'), lo que impide una reparación natural y genera ruido en el prompt del asistente principal.
3. **[susurro_reparacion] Logic Orchestrator (Rule-based override)** — Si el usuario utiliza la estructura gramatical de corrección ('No la X, sino Y'), priorizar la detección de 'Y' sobre el estado actual del canvas, aunque el auditor no haya disparado aún.
   · _por qué_: Zaelar es demasiado literal ('Aquí lo tienes' entregando el reloj) cuando el usuario acaba de decir explícitamente 'abrieras la agenda'. Una regla dura de corrección evitaría esta falta de atención.
