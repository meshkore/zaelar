## Mejoras propuestas (priorizadas — para el equipo de código)

1. **[widget_conducciones] Voice Persona / Gestión de Recovery** — Eliminar la frase hardcoded 'no entiendo... audio cortado' del prompt de recuperación. Sustituir por recuperación silenciosa o verificación positiva de la intención detectada ('Quieres ver la agenda, ¿verdad?') antes de fallar.
   · _por qué_: El sistema penaliza transcripciones válidas excusándose en el audio, frustrando al usuario innecesariamente.
2. **[widget_conducciones] Widget Data / Brain Logic** — Implementar validación estricta en el paso de 'Tool Use': si el LLM no ha extraído un ID o nombre EXACTO para 'widget_data', NO debe responder verbalmente 'Hecho'. Debe forzar un desambiguación ('¿A cuál te refieres, a la X o la Y?') antes de confirmar.
   · _por qué_: El sistema confirmó acción ('Hecho') sobre una tarea que no identificó, lo cual es un fallo de integridad de datos y confianza.
3. **[widget_conducciones] TTS / Turn Endpointing** — Ajustar el timeout de TTS o la longitud de chunks para evitar cortes de sintaxis en lecturas largas (lista de agenda). Asegurar que el turno termine en un punto gramatical.
   · _por qué_: Las frases se truncan a mitad ('...de empre'), rompiendo la coherencia y obligando al usuario a repetir.
4. **[widget_conducciones] Context Injection / Prompting** — Inyectar el último comando del usuario explícitamente en el prompt del sistema (susurro) cuando se retome un turno interrumpido para evitar que el LLM 'pierda el hilo' y repita la lista genérica en lugar de procesar el comando pendiente.
   · _por qué_: Zaelar ignora la petición 'marca como hecha' y vuelve a listar tareas, indicando que el contexto de la tarea activa se pierde en el overlap.
