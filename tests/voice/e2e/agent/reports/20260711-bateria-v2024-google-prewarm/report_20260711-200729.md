## Mejoras propuestas (priorizadas — para el equipo de código)

1. **[busqueda_web] persona / cerebro (prompt system)** — Instrucción explícita para evitar re-preguntar '¿En qué te ayudo?' si el usuario acaba de dar una orden o información inmediatamente después.
   · _por qué_: Zaelar rompe el flujo natural preguntando cómo ayudar cuando ya se le pidió algo (la información del tiempo).
2. **[busqueda_web] brain memory** — Forzar inyección del nombre de usuario en el contexto del prompt del sistema desde el primer turno si existe en memoria.
   · _por qué_: El saludo inicial promete usar el nombre, pero falla en recuperarlo ('Alex' → 'Hola Alex').
3. **[busqueda_web] turn endpointing / dialogue manager** — Implementar 'bypass de relleno' o separación de eventos de pensamiento (thought) vs respuesta final (speech) para que el usuario no oiga el texto de relleno si la respuesta llega inmediatamente después, o descartar turnos si el usuario ya ha confirmado.
   · _por qué_: El eco de 'Déjame que lo mire' y la repetición del turno 3 indican que el sistema no está sincronizando el estado de la conversación con el feedback del usuario.
4. **[busqueda_web] core (nucleo)** — Lógica de detección de cierre: si el usuario dice 'Perfecto/Gracias/Adiós', el sistema debe terminar la interacción y no regurgitar la última respuesta generada.
   · _por qué_: Zaelar repite la información del tiempo después de que el usuario ya despidió, mostrando falta de comprensión del cierre.
